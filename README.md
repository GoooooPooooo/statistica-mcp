# STATISTICA MCP

MCP-сервер для управления STATISTICA 12 через её COM-интерфейс. Позволяет агенту (opencode, Claude Desktop и т.п.) читать и изменять файлы `.sta`/`.stw`, создавать переменные, считать описательные статистики и экспортировать данные.

**Ноль внешних зависимостей.** Node.js реализует протокол MCP сам, PowerShell-worker обращается к COM. `npm install` не нужен.

---

## Требования

| Компонент | Версия | Проверено |
|---|---|---|
| Windows | 10/11 | да |
| Node.js | >= 18 | 24.19.0 |
| STATISTICA 12 | любая | 12.5 |
| PowerShell | 5.1 (системный) | да |

Интернет не требуется.

Проверить, что COM доступен:

```powershell
$app = New-Object -ComObject "STATISTICA.Application"
$app.Visible = $false
$app.Version
$app.Quit()
```

## Установка

1. Распаковать архив в любую папку (например `C:\tools\statistica-mcp`).
2. Добавить сервер в `~/.config/opencode/opencode.jsonc`:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "statistica": {
      "type": "local",
      "command": ["node", "C:\\tools\\statistica-mcp\\statistica\\server.mjs"],
      "enabled": true
    }
  }
}
```

Для Claude Desktop — `%APPDATA%\Claude\claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "statistica": {
      "command": "node",
      "args": ["C:\\tools\\statistica-mcp\\statistica\\server.mjs"]
    }
  }
}
```

3. Перезапустить клиент.

> Путь в конфиге — именно на `server.mjs`. Он определяет расположение `sta.ps1` относительно себя, поэтому папку можно переносить целиком, но нельзя отделять `sta.ps1` от `server.mjs`.

## Проверка установки

В папке проекта:

```bash
node selftest.mjs "C:\путь\к\LAB3.sta"
```

Скрипт создаёт временную копию файла, прогоняет все инструменты и печатает результат. Исходный файл не изменяется.

## Архитектура

```
агент  ──JSON-RPC 2.0 (stdio)──▶  server.mjs  ──запуск процесса──▶  sta.ps1  ──COM──▶  statist.exe
```

- **`server.mjs`** — MCP-сервер. Разбор протокола, схемы инструментов, вычисление описательных статистик на JS. На stdout пишет только JSON-RPC, все логи в stderr.
- **`sta.ps1`** — воркер. Читает JSON-запрос из файла, делает вызовы COM, пишет JSON-ответ в файл. Обмен через файлы, а не через stdout — это снимает проблемы с кодировками кириллицы в PowerShell 5.1.
- Каждый вызов инструмента порождает **новый** процесс `statist.exe` и закрывает его. Состояние между вызовами не сохраняется — это гарантирует корректность, но означает задержку в несколько секунд на вызов.
- Один вызов = один файл `.sta`. Чтобы изменения сохранились, передавайте параметр `save`.

## Инструменты

### `statistica_info`
Проверка доступности COM. Возвращает версию и путь к `statist.exe`. Вызывайте первым, если остальные инструменты не работают.

### `describe_spreadsheet`
Открывает файл и отдаёт размер таблицы и список всех переменных: индекс, короткое имя, длинное имя, тип, уровень измерения.

Параметры: `path` (обязателен), `sheet` (имя или 1-based индекс).

### `read_variables`
Чтение данных. Числовые колонки читаются одним векторным вызовом, текстовые — как строки. Пропуски в числовых возвращаются как `null`.

Параметры: `path`, `sheet`, `variables` (имена или индексы; по умолчанию все), `offset` (с какой строки, 1-based), `limit` (сколько строк).

### `write_variables`
Полная перезапись переменных. Для числовой колонки значение должно быть **ровно на каждое наблюдение**; пропуск — `null`. Для текстовой колонки массив может быть короче — остальные ячейки не трогаются. Без `save` изменения остаются в памяти и отбрасываются.

Параметры: `path`, `columns` (список `{index|name, values}`), `save` (путь для сохранения результата в `.sta`).

### `add_variables`
Добавление пустых переменных. Типы: `0` = numeric, `1` = text, `2` = integer, `3` = byte.

Параметры: `path`, `name`, `longName`, `after` (вставить после этого индекса; `0` = в конец), `count`, `type`, `typeLength`, `save`.

### `rename_variables`
Переименование коротких и/или длинных имён.

Параметры: `path`, `renames` (объект `староеИмя -> новоеИмя`), `longNames`, `save`.

### `delete_variables`
Удаление диапазона переменных включительно.

Параметры: `path`, `from`, `to`, `save`.

### `set_size`
Изменение размера таблицы. Увеличение добавляет пустые ячейки, уменьшение удаляет лишние.

Параметры: `path`, `cases`, `variables`, `save`.

### `export_csv`
Экспорт листа в CSV штатным писателем STATISTICA.

Параметры: `path`, `sheet`, `out`.

### `save_spreadsheet`
Сохранение листа в новый файл. Расширение определяет формат (`.sta`, `.stw`, `.csv`, `.xlsx`).

Параметры: `path`, `sheet`, `out`, `overwrite`, `copy` (`true` = исходник не трогать, по умолчанию).

### `descriptives`
Описательные статистики числовых переменных: N, число пропусков, среднее, sd, se, min, q1, медиана, q3, max, сумма. Считаются в Node.js по данным, прочитанным из COM.

Параметры: `path`, `sheet`, `variables`.

## Особенности COM, на которые наткнулся сервер

Эти выводы — результат экспериментов, их полезно знать при доработке.

- **ProgID `STATISTICA.Application` работает, а `_Application` — нет.** CLSID `{C9E2A000-3D45-11D4-9FF4-00C04FA0D540}` из `STATISTICA.Core.Interop.dll` не зарегистрирован (`0x80040154`). Поэтому сборка interop не используется, всё идёт через `New-Object -ComObject` + `Microsoft.VisualBasic.Interaction::CallByName`.
- **Параметризованные свойства** (`Data(case,var)`, `VData(var)`, `VariableName(n)`) требуют `CallByName` с `CallType::Get` / `::Let`.
- **Массивы маршалятся только типизированные.** `put_VData(n, [double[]])` работает и векторизует запись всей колонки; `object[]` даёт `DISP_E_TYPEMISMATCH`. Поштучная запись — 5.8 мс на ячейку, то есть для таблицы 311×10 неприемлемо медленно.
- **Длина массива должна быть ровно `NumberOfCases`**, иначе `Size Error`.
- **Текст читается только через** `GetData(..., LabelsAsText := True)`. `VData` для текстовой колонки возвращает бессмысленные числа.
- **`GetData` при `nbVars > 1` добавляет метку строки** в начало каждой строки, а при `nbVars = 1` — нет. Чтобы не зависеть от этой особенности, сервер читает колонки по одной.
- **`SaveAsPDF` зависает** в headless-режиме (процесс не завершается даже за 5 минут). Не используется.
- **Методы с `out`-параметрами** (`Statistics`, `ColumnStats`) через `CallByName` не работают (`DISP_E_TYPEMISMATCH`), поэтому статистики считаются в JS.
- **`ConvertTo-Json` в PowerShell 5.1** искажает массивы, созданные через `New-Object object[] N`, оборачивая их в `{"value":[...]}`. Нужно `[object[]]::new(N)` или `ArrayList`.
- Форматы `.sta`/`.stw` проприетарные и двоичные — правка файлов в обход COM невозможна.

## Известные проблемы

1. **`descriptives` неверно считает пропуски.** В файлах код пропуска — `-9999`, а сервер ждёт `-999999998`. В итоге пропуски попадают в выборку, и `min` показывает `-9999`. Затронуты `descriptives` и счётчик пропусков в `read_variables`.
2. **`read_variables` печатает `variable undefined`** вместо номера колонки — воркер не возвращает поле `index`.
3. **`write_variables` не находит переменную по имени**, если она только что добавлена через `add_variables` в том же запросе — `VariableNumber()` не видит её. Работает по числовому индексу.
4. **Имена переменных в файлах STATISTICA часто содержат служебные префиксы** вида `!~\FT1,,,\c0,TS_Nrm` вместо просто `TS_Nrm`. Это формат хранения, а не ошибка; при выборе переменных надёжнее использовать индекс.
5. `save_as`/`export_csv` пишут файл на диск, но иногда нужно подождать — проверяйте размер результата, а не только отсутствие ошибки.

## Доработка

- **Новый инструмент:** добавьте объект в массив `TOOLS` в `server.mjs` (схема + описание) и ветку в `switch (cmd)` файла `sta.ps1`.
- **Формулы STATISTICA** (`=v7*v8`) живут в длинных именах переменных и вычисляются самой программой. Записать формулу через COM не удалось. Если нужно построить производный ряд — проще прочитать две колонки, перемножить в JS и записать результат как обычную числовую колонку.
- **Готовые, но не задействованные методы** (не проверены, использовать с осторожностью): `ShiftVariables`, `StandardizeVariables`, `RankVariables`, `ConcatenateVariables`, `SortData`, `FilterSparseData`, `MergeVariables`.
