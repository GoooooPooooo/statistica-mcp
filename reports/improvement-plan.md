# План доработки STATISTICA MCP

Детальный план развития: текущее состояние → целевое («как должно быть») → приоритеты с критериями приёмки.

- Версия: 2.2 → 2.3
- Среда: Windows, Node.js ≥ 18, PowerShell 5.1 (`powershell.exe`), STATISTICA 12.5 x64

---

## 1. Текущее состояние

Уже реализовано и проверено (`selftest.mjs` — 29/29):

- Открытие `.sta`/`.stw`, чтение/запись значений, учёт пропусков, поиск переменных (в т.ч. по «чистому» имени).
- Правка структуры: `add_variables`, `delete_variables`, `rename_variables`, `set_size`, `save_spreadsheet`.
- Запуск процедур STATISTICA через `run_analysis` (шаги `set`/`call`/`run`/`result`) и самоописание `describe_analysis` / `list_analysis_modules`.
- Пресеты: описательные, корреляция, частоты, t-тест, регрессия (GRM), временные ряды (ACF/PACF, ARIMA, спектр, сглаживание, разности, декомпозиция).
- **Запись формул** (`set_formula`: `VariableLongName` + `Recalculate`).
- **Экспорт графиков** (`statistica_graph` + шаг `saveGraph`) в `.png`/`.jpg`/`.emf`.
- **Режим `attach`** — работа с уже открытым окном STATISTICA без его закрытия.

---

## 2. Целевое состояние («как должно быть»)

1. Агент может выполнить лабораторную работу целиком: от сырых данных до таблиц результатов и рисунков, без ручных кликов в GUI.
2. Любую процедуру STATISTICA можно запустить и получить её результаты таблицами и графиками-файлами.
3. Пользователь может открыть STATISTICA, а MCP — писать формулы/значения прямо в его документ, видя обновление в реальном времени.
4. Один вызов = предсказуемый результат; ошибки — понятные, не разрушающие данные.

---

## 3. Принципы

- **Ноль зависимостей.** Только Node.js + PowerShell 5.1 + COM.
- **Файловый обмен** запрос/ответ (снимает проблемы кодировок).
- **Stateless по умолчанию**, `attach` — явный режим для живого окна.
- **Сохранение только по явному `save`.**
- **Расширяемость данными, а не кодом:** таблицы модулей и enum-констант вынесены в server.

## 5. Целевой сценарий (ЛР3 «Модели корреляции НВР»)

Как должно быть по шагам MCP (пример будущего пайплайна):

1. `describe_spreadsheet` → найти `TS_Nrm`.
2. `statistica_time_series { procedure: "autocorrelation", lags: 15, out: "...\acf.png" }` → график АКФ.
3. `run_analysis` (TS, `TypeOfTransformation=3`, `ShiftSeriesForward`, lag 1) → задержанный ряд; `saveGraph` рисунка.
4. `set_formula { variable: "TS_Prod", formula: "v9*v10" }` → корреляционное произведение.
5. `statistica_time_series { procedure: "smoothing", window: 12 }` → непараметрическая оценка; рисунок.
6. `statistica_regression { dependent: <оценка>, predictors: [<индекс>] }` → параметрическая линейная модель (наклон/сдвиг).
7. `statistica_correlation_matrix { variable: "TS_Nrm", lags: 12 }` → таблица `Lag1..Lag12`.
8. `statistica_graph { module: 11021/11032, variables: "Lag1 | … | Lag12", out: "...\3d.png" }` → 3D-график.

Пункты 1–7 выполнимы: пункт 4 — через `set_formula`, пункт 7 — пресет `statistica_correlation_matrix` (реализован в v2.2). Пункт 8 (3D-график) — через `statistica_graph` / `saveGraph`.

## 7. Риски

| Риск | Митигация |
|---|---|
| Капризные свойства COM (как `TypeOfTransformation`) | Перебирать варианты значений, фиксировать рабочий в отчёте и таблице enum-ов |
| Незакрытые окна STATISTICA при `attach` | Не вызывать `Quit` в режиме `attach`; проверять PID |
| Большие таблицы результатов | Ограничение строк/столбцов при маршалинге, пометка об усечении |
| Ошибки кодировок кириллицы | Обмен только через UTF-8 файлы, без stdout |
