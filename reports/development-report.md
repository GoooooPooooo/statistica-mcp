# Отчёт о доработке STATISTICA MCP

Промежуточный технический отчёт: эксплуатационные проблемы, гипотезы, методы решения и результат.

- Проект: `statistica-mcp`
- Версия на момент отчёта: 2.0.0
- Среда: Windows 10/11, Node.js 24, PowerShell 5.1 (`powershell.exe`), STATISTICA 12.5.192.7 (x64)
- Проверочный файл: `ЛАБ3\LAB2.sta` (156 наблюдений, 18 переменных, временной ряд `SERIES_G`)

---

## 1. Постановка

Исходный сервер (v1.0.0) умел открывать `.sta`, читать/писать переменные, экспортировать CSV и считать описательные статистики **на JavaScript** по данным, вычитанным через COM. Задача — довести MCP до состояния, в котором с STATISTICA можно работать полноценно: запускать собственные процедуры программы (базовая статистика, корреляция, t-тесты, регрессия, временные ряды), а не подменять их расчётами на стороне агента.

## 2. Эксплуатационные проблемы, гипотезы и решения

Формат: **проблема → гипотеза → метод решения → результат**.

### П-1. Неверный учёт пропусков (v1, серьёзность высокая)

- **Проблема.** `descriptives` показывал `min = -9999` и `missing = 0`: код пропуска попадал в выборку.
- **Гипотеза.** COM-чтение сравнивало ячейку только с одним маркером `-999999998`, тогда как у переменной может быть собственный код пропуска (`VariableMissingData`), в `LAB2.sta` он равен `-9999`.
- **Решение.** В `Read-Variable` читать `VariableMissingData(var)` и считать пропуском оба маркера; тест-кейс в `selftest.mjs`.
- **Результат.** Пропуски возвращаются как `null`, статистики корректны. Коммит `bf15f92`.

### П-2. `variable undefined` и захламлённые имена

- **Проблема.** `read_variables` печатал `variable undefined`; имена имели вид `!~\FT1,,,\c0,SERIES_G`.
- **Гипотеза.** Воркер не возвращал `index`, а префикс — служебная часть хранения короткого имени.
- **Решение.** Добавлено поле `index`; функции `Get-CleanName` (всё после последней запятой для имён с префиксом `!~\`); поиск переменной принимает и полное, и «чистое» имя; в `describe_spreadsheet` добавлена колонка «missing».
- **Результат.** `variable 2: SERIES_G`, поиск по `SERIES_G` работает. Коммит `bf15f92`.

### П-3. Новая переменная не находится по имени

- **Проблема.** `write_variables` по имени переменной, созданной в той же сессии, падал.
- **Гипотеза.** `VariableNumber(name)` не видит переменные, добавленные через `AddVariables`, до сохранения файла.
- **Решение.** Линейный перебор `VariableName(k)` как fallback, плюс сопоставление по «чистому» имени.
- **Результат.** Поиск устойчив. Коммит `bf15f92`.

### П-4. Путаница с индексом листа

- **Проблема.** `sheetIndex: 0`, если лист не задан.
- **Решение.** `Open-Sheet` возвращает и запоминает реальный `1-based` индекс и имя (`$script:sheetIndex`, `$script:sheetName`).
- **Результат.** `Sheet: LAB2.sta (index 1)`. Коммит `bf15f92`.

### П-5. Гонка при записи файла

- **Проблема.** CSV/`.sta` иногда ещё не существовал сразу после возврата `SaveAs`.
- **Решение.** `Wait-File` — до 20 повторов с паузой 250 мс перед чтением размера.
- **Результат.** Стабильный `bytes`. Коммит `bf15f92`.

### П-6. Ключевая задача: запуск процедур STATISTICA

- **Проблема.** Нужно не пересчитывать статистику в JS, а вызывать сам движок STATISTICA.
- **Гипотеза.** COM-интерфейс `Application.Analysis(AnalysisIdentifier, Variant)` возвращает объект анализа, у которого `.Dialog` — диалог процедуры, `.Run` — запуск, а свойства результатов (`Summary` и др.) — таблицы.
- **Как искали.** Загрузили `STATISTICA.Analysis.Interop.dll` и `STATISTICA.Core.Interop.dll` через .NET-рефлексию, перечислили `AnalysisIdentifier` (например, `scBasicStatistics = 1301`, `scMultipleRegression = 1701`, `scTimeSeries = 1901`, `scGRM = 4601`), изучили примеры StatSoft (`Examples\Macros`, `DataMiner\*.svx`).
- **Решение.** Универсальный движок `run_analysis` со «шагами»: `{"set": {...}}`, `{"call": "Method"}`, `{"run": true}`, `{"result": "Property"}`. Плюс `describe_analysis` (перечисляет свойства/методы диалога и известные enum-константы) и `list_analysis_modules`. Результаты маршалятся из COM в таблицы/массивы/идентификаторы документов (график, отчёт).
- **Результат.** Любая процедура STATISTICA доступна агенту. Коммит `bf15f92`, дополнения — далее.

### П-7. Массивы аргументов в PowerShell ломали вызовы COM

- **Проблема.** `CallByName(...)` падал «No default member found for type 'String'» / «number of parameters mismatch».
- **Гипотеза.** Имя параметра `$args` конфликтует с автоматической переменной PowerShell, а `@($value)` разворачивает массив-значение в список аргументов.
- **Решение.** Хелперы `comGet/comSet/comCall` строят `[object[]]` вручную; для присваивания свойства одним значением (в т.ч. массивом) — `comSetOne`.
- **Результат.** Установка `Variables`, `VData` и др. работает. Коммит `bf15f92`.

### П-8. `TypeOfTransformation` в модуле Time Series: Access Violation

- **Проблема.** Установка `TypeOfTransformation = 1073741825` (сглаживание) падала «Access Violation»; сглаживание фактически **не применялось** (исходный и сглаженный столбцы совпадали).
- **Гипотезы и проверки.**
  1. *Гипотеза «виноват CallByName»* — опровергнута: нативное присваивание `$d.TypeOfTransformation = ...` падало так же.
  2. *Гипотеза «не тот тип значения»* — проверена: маленькое `1` устанавливалось успешно, а `1073741825` падало.
  3. *Гипотеза «флаг 0x40000000»* — подтверждена: константы time series в type library равны `0x40000000 + индекс` (`scTimSmoothingTransformations = 0x40000001`), а сеттер свойства принимает **индекс без флага**.
- **Решение.** В пресетах time series передавать `TypeOfTransformation = константа − 0x40000000` (`Smoothing = 1`, `Fourier = 5`, `Autocorrelation = 7`, `Descriptive = 8`, `Differencing = 4`). Таблица соответствий добавлена в `describe_analysis`.
- **Результат.** Сглаживание реально применяется (142 из 144 ячеек отличаются), предупреждение исчезло. Коммит `408daea`.

### П-9. Регрессия: `Summary` недоступен

- **Проблема.** У классического модуля `scMultipleRegression = 1701` свойство `.Summary` возвращало `null`; `.Variables` при пустом значении давало «Invalid variable selection».
- **Гипотезы.**
  1. Модуль 1701 — многошаговый «мастер» (RegStartup → RegModel → результаты), результаты берутся через параметризованное `Summary(1)`.
  2. Либо надёжнее использовать современный `scGRM = 4601` («General Regression Models»), который применяется в самом DataMiner.
- **Решение.** Пресет `statistica_regression` построен на `scGRM` с `GRMAnalysisItem = 1`, строкой `Variables = "dep | predictors"` и чтением таблиц `.Coefficients` и `.UnivariateResults`. Флаги метода (`RegressionAllEffectsIncluded`, `ForwardStepwiseRegression`, `BackwardStepwiseRegression`) заданы по именам из DataMiner; для «standard» ничего не задаётся (по умолчанию).
- **Результат.** Коэффициенты и ANOVA возвращаются. Коммит `408daea`.

### П-10. `rename_variables` не принимал числовые ключи

- **Проблема.** `renames: { "1": "NEW" }` падало: ключ JSON — строка, а поиск трактовал её как имя.
- **Решение.** В `Get-VarIndex` строку вида `^\d+$` считать индексом.
- **Результат.** Переименование по числовому ключу работает. Коммит `352e2a5`.

### П-11. ARIMA: `NumberOfCasesToForecast` не найден

- **Проблема.** Установка числа прогнозов до `Run` падала.
- **Гипотеза.** По примеру StatSoft свойство задаётся **после** запуска, на диалоге результатов.
- **Решение.** В пресете `arima` шаг `{set:{NumberOfCasesToForecast}}` перенесён после `{run:true}`.
- **Результат.** Прогнозы выдаются ровно в нужном количестве. Коммит `bf15f92`.

### П-12. Импорт CSV: одна колонка вместо нескольких

- **Проблема.** `ImportTextAutoEx` с неверным `TextImportQualifier = 0` импортировал файл одной переменной.
- **Гипотеза.** Enum `TextImportQualifier` начинается с `0x40000000` (`None = 1073741824`, `DoubleQuote = 1073741825`).
- **Решение.** Передавать `1073741825`; при отсутствии разделителя — `ImportTextAuto` (автоопределение), при заданном — `ImportTextAutoEx` с разделителем.
- **Результат.** Импорт 3 столбцов из `x;y;label` корректен. Коммит `bf15f92`.

### П-13. Git-предупреждения о переводах строк

- **Проблема.** `git add` писал `LF will be replaced by CRLF`.
- **Причина.** `core.autocrlf=true`.
- **Решение.** `.gitattributes` c `* text=auto eol=lf`; рабочее дерево нормализовано в LF.
- **Результат.** Предупреждений нет. Коммит `b210540`.

### П-14. SSH: `Permission denied (publickey)`

- **Проблема.** Ключ не подходил, при том что GitHub его «принимал».
- **Гипотеза.** Ключ был зашифрован паролем из-за кавычек PowerShell (`-N '""'` → пароль `""`), а `BatchMode` не мог его расшифровать.
- **Решение.** `ssh-keygen -p -P '""' -N ''` снял пароль; материал ключа и отпечаток не изменились, регистрация на GitHub осталась валидной.
- **Результат.** `Hi GoooooPooooo! You've successfully authenticated`. (Действия с репозиторием, не с кодом MCP.)

## 5. Ограничения (осознанные)

1. **По умолчанию stateless.** Каждый вызов поднимает и закрывает `statist.exe` — задержка в несколько секунд; изменения на диск попадают только с явным `save`. Режим `attach` (раздел 7) работает с уже открытым окном без закрытия.
2. **Методы с `out`-параметрами** (`Statistics`, `ColumnStats`) недоступны через `CallByName` — часть статистик считается в Node.
3. **Пресеты** покрывают популярные сценарии; полный доступ — через `run_analysis`/`describe_analysis`.
4. **Графики** сохраняются как изображения (`.png`/`.jpg`/`.emf`); интерактивного редактирования графов нет.

## 6. Итог

MCP из «читалки/писалки файлов» превращён в полноценный драйвер STATISTICA: сервер запускает собственные процедуры программы, возвращает их таблицы, пишет формулы, экспортирует графики и предоставляет агенту инструменты самоописания для произвольных анализов. Все 29 автопроверок проходят, дефекты из разделов 2 и 7 устранены и зафиксированы отдельными коммитами.

## 7. Продолжение: проблемы доработки v2.1

### П-15. Экспорт графиков

- **Проблема.** Лабораторные задания требуют рисунков, а MCP возвращал графики как дескрипторы документов без файла.
- **Гипотеза.** У Graph-объекта есть метод `SaveAs`, который пишет изображение по расширению.
- **Как искали.** Построили 2D-диаграмму рассеяния (`sc2dScatterplots = 11003`) и перечислили методы полученного объекта: найдены `ExportEx`, `Save`, `SaveAs`, `SaveAsFormat`.
- **Решение.** `ExportEx(path)` ожидает другой набор аргументов, а `Graph.SaveAs(path)` уверенно пишет файл; для графовых модулей чтение `.Graphs` само строит график (без `Run`). Добавлен шаг `{"saveGraph": "path.png", "result": "Graphs"}` и инструмент `statistica_graph`.
- **Результат.** `scatter.png` и `surface.png` создаются автоматически (проверено, magic `89 50 4E 47`). Проверка `graph build + export png` в self-test.

### П-16. Запись формул STATISTICA

- **Проблема.** Ранее считалось, что формулы через COM не записать.
- **Гипотеза.** Формула хранится в длинном имени переменной, а `VariableLongName` — индексируемое свойство с аксессором `Set`; `CallByName` с `Let`/`Set` его не берёт.
- **Как искали.** Ошибка CallByName прямо подсказала «Use CallType.Set»; просмотр макросов StatSoft дал шаблон:
  ```
  ssout.VariableLongName(2) = "=v1-v2"
  ssout.Recalculate(2)
  ```
- **Решение.** Присваивать длинное имя нативно (`Set-LongName`, с fallback через `InvokeMember`), затем вызывать `Recalculate(idx)`. Добавлен инструмент `set_formula`.
- **Результат.** `=v1*2` даёт 2, 4, 6, …; `=v2*2` даёт 224, 236, 264, … Проверка `set formula on a variable` в self-test.

### П-17. Работа «в реальном времени» с открытым окном

- **Проблема.** Stateless-режим не влияет на уже открытую пользователем программу.
- **Гипотеза.** `Marshal.GetActiveObject('STATISTICA.Application')` подключается к запущенному экземпляру; он есть в .NET Framework (PowerShell 5.1), хотя отсутствует в .NET Core (PowerShell 7).
- **Решение.** Флаг `attach`: worker берёт активный экземпляр через `GetActiveObject`, работает с его активным листом и **не закрывает** приложение; добавлен во все инструменты данных/анализа.
- **Результат.** Кросс-процессный тест: worker подключился к чужому окну (PID совпал), записал формулу и значения, окно осталось живым (`still alive pid=… same=True`).
