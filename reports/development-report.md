# Отчёт о доработке STATISTICA MCP

Промежуточный технический отчёт: эксплуатационные проблемы, выдвинутые гипотезы (принятые и отвергнутые с обоснованием), методы решения и результат.

- Проект: `statistica-mcp`
- Версия на момент отчёта: 2.3.0
- Среда: Windows 10/11, Node.js 24, PowerShell 5.1 (`powershell.exe`), STATISTICA 12.5.192.7 (x64)
- Проверочный файл: `ЛАБ3\LAB2.sta` (156 наблюдений, 18 переменных, временной ряд `SERIES_G`)

---

## 1. Постановка

Исходный сервер (v1.0.0) умел открывать `.sta`, читать/писать переменные, экспортировать CSV и считать описательные статистики **на JavaScript** по данным, вычитанным через COM. Задача — довести MCP до состояния, в котором с STATISTICA можно работать полноценно: запускать собственные процедуры программы (базовая статистика, корреляция, t-тесты, регрессия, временные ряды), записывать формулы, строить и сохранять графики, а также при необходимости работать с уже открытым окном «вживую».

---

## 2. Методика разбора

Для каждой проблемы формулировалось **несколько конкурирующих гипотез**. Затем каждая проверялась минимальным экспериментом (отдельный PowerShell-скрипт или запрос к COM). Гипотеза **отвергалась**, если эксперимент давал результат, несовместимый с ней (иное сообщение об ошибке, отсутствие ожидаемого эффекта, регресс). Гипотеза **принималась**, если её следствие устойчиво подтверждалось и давало искомый результат. Ниже для каждой проблемы указаны все рассмотренные гипотезы с вердиктом и причиной, принятое решение и итог.

## 3. Проблемы, гипотезы и решения

### П-1. Пропуски не распознаются (серьёзность высокая)

**Проблема.** `descriptives` показывал `min = -9999`, `missing = 0`: код пропуска попадал в выборку и искажал среднее/минимум.

**Гипотезы:**

- **H1. Достаточно сравнивать ячейку с одним маркером `-999999998`.** — *Отвергнута.* В `LAB2.sta` `describe_spreadsheet` показал `missingValue = -9999` у ряда переменных; значение `-9999` не равно `-999999998`, поэтому проверка его не ловила.
- **H2. `VData` возвращает `-9999` как обычное число, и `-9999` — это объявленный код пропуска переменной.** — *Принята.* Поле `VariableMissingData(var)` для тех же переменных вернуло `-9999`; значение совпало с наблюдаемым в данных.
- **H3. Метод `VDataWithoutMD` вернёт колонку сразу без пропусков, и проверки не нужны.** — *Отложена/не подтверждена.* Прямого выигрыша не проверяли, так как H2 уже давала корректный результат и не зависела от поведения недокументированного метода.

**Решение.** В `Read-Variable` читать `VariableMissingData(var)` и считать пропуском **оба** маркера: глобальный `-999999998` и объявленный код переменной.

**Итог.** Пропуски возвращаются как `null`, статистики корректны. Коммит `bf15f92`.

### П-2. `read_variables` печатает `variable undefined`

**Проблема.** Вывод `variable undefined: !~\FT1,,,\c0,SERIES_G`.

**Гипотезы:**

- **H1. Ошибка в форматировании на стороне сервера (неправильная подстановка).** — *Отвергнута.* Шаблон в `server.mjs` подставлял `d.index`; при `index === undefined` печаталось `undefined`.
- **H2. Воркер не возвращает поле `index`.** — *Принята.* Функция `Read-Variable` формировала ответ без `index`, поэтому серверу нечего было подставить.

**Решение.** Добавить `index = $idx` в результат `Read-Variable`.

**Итог.** `variable 2: SERIES_G`. Коммит `bf15f92`.

---

### П-3. `write_variables` не находит переменную по имени

**Проблема.** Переменная, добавленная через `AddVariables` в текущей сессии, не находилась по имени.

**Гипотезы:**

- **H1. `VariableNumber` не работает в принципе.** — *Отвергнута.* Для переменных, загруженных из файла (например `Res_1`), `VariableNumber` возвращал корректный индекс.
- **H2. Внутренний индекс имён не обновляется для только что созданных переменных до сохранения.** — *Принята.* Сразу после `describe` переменная видна, но `VariableNumber` её не находит; после сохранения и повторного открытия поиск работает.

**Решение.** В `Get-VarIndex` при неудаче `VariableNumber` выполнять линейный перебор по `VariableName(k)` (сопоставление и по полному, и по «чистому» имени).

**Итог.** Поиск устойчив. Коммит `bf15f92`.

---

### П-4. Служебные префиксы в именах переменных

**Проблема.** Имена вида `!~\FT1,,,\c0,TS_Nrm`.

**Гипотезы:**

- **H1. Это дефект чтения/повреждение данных.** — *Отвергнута.* Заголовки стабильны и одинаковы у всех «формульных» переменных; это формат хранения, а не ошибка.
- **H2. Префикс `!~\...` — служебная часть, а собственно имя стоит после последней запятой.** — *Принята.* Для `!~\FT1,,,\c0,TS_Nrm` часть после последней запятой — `TS_Nrm`; для имени без префикса (`NewVar2`) разбор не меняет строку.

**Решение.** Функция `Get-CleanName` (обрезает только при наличии префикса `!~\`); поиск принимает полное и чистое имя; в выводе добавлены обе формы.

**Риски (учтены).** Если имя законно содержит запятую — возможно усечение; при совпадении «чистых» имён приоритет у точного полного совпадения.

**Итог.** `describe_spreadsheet` показывает `name` и `cleanName`. Коммит `bf15f92`.

### П-5. `sheetIndex: 0` без явного листа

**Проблема.** `describe_spreadsheet` без `sheet` сообщал индекс 0.

**Гипотезы:**

- **H1. Нужно вычислять индекс по имени листа.** — *Отвергнута как избыточная.* Имя уже известно; проблема только в отсутствии индекса по умолчанию.
- **H2. `[int]$req.sheet` при `null` даёт 0, и это значение попадает в ответ.** — *Принята.* Требовалось вернуть фактически использованный индекс из `Open-Sheet`.

**Решение.** `Open-Sheet` запоминает реальные `$script:sheetIndex` и `$script:sheetName`; `describe` возвращает их.

**Итог.** `Sheet: LAB2.sta (index 1)`. Коммит `bf15f92`.

### П-6. Файл может быть не записан к моменту возврата

**Проблема.** Один раз после `SaveAs` CSV файл сразу не находился.

**Гипотезы:**

- **H1. `SaveAs` вообще не создаёт файл.** — *Отвергнута.* При повторной попытке файл появлялся и имел корректный размер.
- **H2. Задержка фактической записи на диск (буферизация) — гонка.** — *Принята.* Поведение согласуется с временным отсутствием файла и успехом при повторе.

**Решение.** `Wait-File` — до 20 повторов с паузой 250 мс перед чтением размера.

**Итог.** Стабильный `bytes`. Коммит `bf15f92`.

### П-7. Как запускать собственные процедуры STATISTICA

**Проблема.** Требовалось вызывать движок STATISTICA, а не пересчитывать статистику в JS.

**Гипотезы:**

- **H1. Использовать `_Application`/CLSID из interop-сборки.** — *Отвергнута.* CLSID из `STATISTICA.Core.Interop.dll` не зарегистрирован, `New-Object` давал `0x80040154`.
- **H2. `Analysis(id, "1-3")` принимает строку со списком переменных.** — *Отвергнута.* Вызов падал с «Could not open Spreadsheet»: вторым аргументом ожидается не строка, а объект листа.
- **H3. `Analysis(id, spreadsheet)` возвращает объект анализа; `.Dialog` — диалог процедуры, `.Run` — запуск, свойства результатов (`Summary` и др.) — таблицы.** — *Принята.* Подтверждено на модулях 1301 (описательные/корреляция), 1901 (временные ряды), 11003 (график).
- **H4. Любое свойство результата возвращает таблицу.** — *Отвергнута как обобщение.* Часть свойств параметризована (`Summary(1)`), часть возвращает массив документов (`Autocorrelations`), график или `null`; результат-график у некоторых модулей доступен через `.Graphs`, а прямой `Run` у графического модуля даёт `E_UNEXPECTED`.

**Как искали.** Загрузили `STATISTICA.Analysis.Interop.dll` и `STATISTICA.Core.Interop.dll` через .NET-рефлексию, перечислили `AnalysisIdentifier` (`scBasicStatistics = 1301`, `scMultipleRegression = 1701`, `scTimeSeries = 1901`, `scGRM = 4601`), изучили примеры StatSoft (`Examples\Macros`, `DataMiner\*.svx`).

**Решение.** Универсальный движок `run_analysis` со «шагами» `set`/`call`/`run`/`result`/`saveGraph`; инструменты `describe_analysis` (самоописание диалога и enum-константы) и `list_analysis_modules`. Результаты маршалятся в таблицы/массивы/дескрипторы документов.

**Итог.** Любая процедура доступна агенту. Коммиты `bf15f92`, `628fe39`, `b41eb5d`.

### П-8. `CallByName` падает при передаче массивов

**Проблема.** Ошибки «No default member found for type 'String'» и «Number of parameters specified does not match».

**Гипотезы:**

- **H1. `CallByName` в принципе несовместим с COM STATISTICA.** — *Отвергнута.* Скалярные операции (`VariableName(n)` и др.) через `CallByName` работали.
- **H2. Имя параметра `$args` конфликтует с автоматической переменной PowerShell, а `@($value)` разворачивает массив-значение в список аргументов.** — *Принята.* После переименования параметра и ручной сборки `[object[]]` вызовы заработали.

**Решение.** Хелперы `comGet/comSet/comCall` строят `[object[]]` вручную; для присваивания свойства одним значением (в т.ч. массивом) — `comSetOne`.

**Итог.** Установка `Variables`, `VData` и др. работает. Коммит `bf15f92`.

### П-9. `TypeOfTransformation` (Time Series): Access Violation

**Проблема.** Установка `TypeOfTransformation = 1073741825` (сглаживание) падала; сглаживание **не применялось** (исходный и сглаженный столбцы совпадали).

**Гипотезы:**

- **H1. Виноват `CallByName`.** — *Отвергнута.* Нативное присваивание `$d.TypeOfTransformation = ...` падало так же («Access Violation»).
- **H2. Неверный тип значения (Int64 вместо Int32).** — *Отвергнута.* Приведение к Int32 в `Convert-JsonValue` не устранило падение.
- **H3. Свойство принимает значение с флагом `0x40000000` (как в type library).** — *Отвергнута.* Малое значение `1` устанавливалось успешно, а `1073741825` (=`0x40000001`) падало.
- **H4. Сеттер ждёт «сырой» индекс без флага: `константа − 0x40000000`.** — *Принята.* `Smoothing = 1`, `Fourier = 5`, `Autocorrelation = 7`, `Descriptive = 8`, `Differencing = 4`; сглаживание при `1` реально применилось.

**Решение.** В пресетах time series передавать индекс без флага; таблица соответствий добавлена в `describe_analysis`.

**Итог.** Сглаживание применяется (142 из 144 ячеек отличаются), предупреждение исчезло. Коммит `408daea`.

### П-10. Регрессия не отдаёт результаты

**Проблема.** У модуля `scMultipleRegression = 1701` свойство `.Summary` возвращало `null`.

**Гипотезы:**

- **H1. Нужно читать `.Summary(1)` (параметризованное свойство).** — *Отвергнута.* Ни `Summary` без аргумента, ни `Summary(1..4)` не давали таблицу: модуль 1701 — многошаговый «мастер» (RegStartup → RegModel → результаты).
- **H2. Дело в порядке установки `PerformDefaultNonStepwiseAnalysis`.** — *Отвергнута.* Перестановка и повторные `Run` результат не меняли.
- **H3. Надёжнее использовать современный `scGRM = 4601`.** — *Принята.* В GRM таблицы результатов доступны как `.Coefficients` и `.UnivariateResults` (этот модуль применяет и сам DataMiner).
- **H4 (частная). Для метода задавать свойство `RegressionStandard`.** — *Отвергнута.* Такого члена у `GLMSpecifications` нет; для «standard» ничего задавать не нужно, для остальных — `RegressionAllEffectsIncluded` / `ForwardStepwiseRegression` / `BackwardStepwiseRegression`.

**Решение.** Пресет `statistica_regression` на `scGRM`: `GRMAnalysisItem = 1`, `Variables = "dep | predictors"`, чтение `.Coefficients` и `.UnivariateResults`; флаги только для не-`standard` методов.

**Итог.** Коэффициенты и ANOVA возвращаются. Коммит `408daea`.

### П-11. `rename_variables` не принимает числовые ключи

**Проблема.** `renames: { "1": "NEW" }` падало.

**Гипотезы:**

- **H1. Ключи JSON приходят числами и потому распознаются как индекс.** — *Отвергнута.* В JSON ключ объекта — всегда строка; воркер видел `"1"` как имя и искал переменную с именем `1`.
- **H2. Строковый ключ вида `^\d+$` нужно трактовать как индекс.** — *Принята.* После добавления ветки переименование по числовому ключу заработало.

**Решение.** В `Get-VarIndex` строка `^\d+$` → числовой индекс.

**Итог.** Коммит `352e2a5`.

---

### П-12. ARIMA: `NumberOfCasesToForecast` не найден

**Проблема.** Установка числа прогнозов до `Run` падала («member not found на TimARIMA»).

**Гипотезы:**

- **H1. Свойство задаётся до запуска, как параметры модели.** — *Отвергнута.* На этапе модели такого члена нет.
- **H2. Свойство задаётся после `Run`, на диалоге результатов.** — *Принята.* По примеру StatSoft `NumberOfCasesToForecast` устанавливается после запуска; прогноз выдаётся ровно в нужном количестве.

**Решение.** В пресете `arima` шаг `{set:{NumberOfCasesToForecast}}` перенесён после `{run:true}`.

**Итог.** Коммит `bf15f92`.

### П-13. Импорт CSV: одна колонка вместо нескольких

**Проблема.** `ImportTextAutoEx` импортировал файл одной переменной.

**Гипотезы:**

- **H1. Значение `TextImportQualifier = 0` корректно.** — *Отвергнута.* Документация/type library: enum начинается с `0x40000000` (`None = 1073741824`, `DoubleQuote = 1073741825`).
- **H2. Нужно передавать `1073741825`.** — *Принята.* При корректном квалификаторе и разделителе импортируются все колонки.

**Решение.** Передавать `1073741825`; без разделителя — `ImportTextAuto` (автоопределение), с разделителем — `ImportTextAutoEx`.

**Итог.** Импорт `x;y;label` — 3 переменные. Коммит `bf15f92`.

### П-14. Git-предупреждения о переводах строк

**Проблема.** `git add` писал `LF will be replaced by CRLF`.

**Гипотезы:**

- **H1. Отключить `core.autocrlf` глобально.** — *Отвергнута.* Это меняло бы глобальную конфигурацию пользователя и влияло на другие репозитории.
- **H2. Задать политику переводов на уровне проекта через `.gitattributes`.** — *Принята.* `* text=auto eol=lf` перекрывает `core.autocrlf` и снимает предупреждение, не трогая глобальные настройки.

**Решение.** Добавлен `.gitattributes`; рабочее дерево нормализовано в LF.

**Итог.** Предупреждений нет. Коммит `b210540`.

### П-15. SSH: `Permission denied (publickey)`

**Проблема.** `git push` не проходил, при том что GitHub печатал «Server accepts key».

**Гипотезы:**

- **H1. Публичный ключ не добавлен в GitHub.** — *Отвергнута.* Сервер «принимал» ключ, значит ключ зарегистрирован; сбой происходил уже на подписи.
- **H2. Приватный ключ зашифрован паролем, который не удаётся ввести в неинтерактивном режиме.** — *Принята.* `ssh-keygen -y` сообщил «incorrect passphrase supplied»; причина — кавычки PowerShell при генерации (`-N '""'` задало пароль `""`).

**Решение.** `ssh-keygen -p -P '""' -N ''` снял пароль; материал ключа и отпечаток не изменились, регистрация на GitHub осталась валидной.

**Итог.** `Hi GoooooPooooo! You've successfully authenticated`. (Действия с репозиторием, не с кодом MCP.)

### П-16. Графики не сохранялись в файлы

**Проблема.** Задания требуют рисунков, а MCP возвращал графики как дескрипторы без файла.

**Гипотезы:**

- **H1. `Graph.ExportEx(path)` пишет изображение.** — *Отвергнута.* Ошибка преобразования аргумента: `ExportEx` ожидает другой набор параметров.
- **H2. `Graph.SaveAs(path)` пишет изображение по расширению.** — *Принята.* `SaveAs` вернул `True` и создал валидный PNG (сигнатура `89 50 4E 47`).
- **H3. Графическим модулям нужен явный `Run`.** — *Отвергнута.* Вызов `Run` у модуля 11003 давал `E_UNEXPECTED`; чтение `.Graphs` само строит график (как в макросах StatSoft).

**Решение.** Шаг `{"saveGraph": "path.png", "result": "Graphs"}` и инструмент `statistica_graph`.

**Итог.** `scatter.png`, `surface.png` создаются автоматически. Коммит `628fe39`.

### П-17. Запись формул STATISTICA

**Проблема.** Ранее считалось, что формулы (`=v7*v8`) через COM записать нельзя.

**Гипотезы:**

- **H1. Формулы через COM не записываются в принципе.** — *Отвергнута.* Макросы StatSoft задают формулы через `VariableLongName` и `Recalculate`.
- **H2. Формулу можно записать через `SetData` строкой.** — *Отвергнута.* `SetData` со строкой-формулой даёт `DISP_E_MEMBERNOTFOUND`/ошибку типа.
- **H3. `VariableLongName` через `CallByName` с `Let`.** — *Отвергнута.* «Public Let `VariableLongName` … not found. Use CallType.Set».
- **H4. `VariableLongName` через `CallByName` с `Set`.** — *Отвергнута.* `DISP_E_MEMBERNOTFOUND`: это индексируемое свойство, а не метод с двумя аргументами.
- **H5. Нативное присваивание параметризованного свойства `VariableLongName(idx) = "=..."` + `Recalculate(idx)`.** — *Принята.* `=v1*2` даёт 2, 4, 6, …; `=v2*2` даёт 224, 236, 264, …

**Решение.** Хелпер `Set-LongName` (нативное присваивание, fallback — `InvokeMember SetProperty`), затем `Recalculate(idx)`; инструмент `set_formula`. Также исправлена установка длинных имён в `rename_variables`.

**Итог.** Формулы пишутся и вычисляются. Коммит `b41eb5d`.

### П-18. Работа «в реальном времени» с уже открытым окном

**Проблема.** Stateless-режим не влияет на открытую пользователем программу.

**Гипотезы:**

- **H1. `Marshal.GetActiveObject` отсутствует в .NET вообще.** — *Отвергнута.* Метод есть в .NET Framework; ошибка возникала только в PowerShell 7 (.NET Core). Worker запускается в PowerShell 5.1, где метод доступен.
- **H2. Подключившись к активному экземпляру, можно править его и не закрывать.** — *Принята.* Кросс-процессный тест: worker подключился к экземпляру из другого процесса (PID совпал), записал формулу и значения, окно осталось живым.

**Решение.** Флаг `attach`: worker получает активный экземпляр через `GetActiveObject`, работает с его активным листом и **не вызывает `Quit`**; флаг добавлен во все инструменты данных/анализа.

**Итог.** Живое редактирование открытого документа. Коммит `b41eb5d`.

# Часть II. Доработка v2.2 (пункты P1 плана)

Продолжение отчёта по тому же принципу: проблема → конкурирующие гипотезы → эксперимент → принятое решение → итог. Реализованы пункты 4, 5, 6, 7, 9 плана `improvement-plan.md`.

## 9. Имена наблюдений (P1 #6)

**Проблема.** Лабораторные `.sta` хранят метки строк (`JAN 1949`, …); при чтении/правке данных метки терялись, а задать их через MCP было нельзя.

**Гипотезы:**

- **H1. Метка строки доступна только через `GetData` с `LabelsAsText`.** — *Отвергнута.* Этот путь даёт значения ячеек, а не имена наблюдений.
- **H2. У листа есть индексируемое свойство `CaseName(i)` с аксессорами Get и Let.** — *Принята.* Рефлексия по `STATISTICA.Core.Interop.dll` показала `PROP String CaseName(Int32 CaseNo)`. Эксперимент: `CaseName(1)` вернул `JAN 1949`, а присваивание через `CallByName Let` изменило имя.

**Решение.** Команда воркера `case_names`: при наличии `names` пишет их по порядку (case 1, 2, …), затем возвращает прочитанные имена. Инструмент `case_names` с опциональным `save`/`attach`.

**Итог.** Чтение и запись имён работают; в self-test — `named: 156`.

## 10. Сортировка (P1 #9)

**Проблема.** Требовалась сортировка таблицы по ключам с сохранением соответствия строк и их меток.

**Гипотезы:**

- **H1. `SortDataEx` принимает массив ключей (мультисортировка одним вызовом).** — *Отвергнута.* Вызов с `Variables=[1,2]` дал `Invalid variable list`.
- **H2. `SortDataEx(Variables, Direction, By, false, true)` сортирует по одному ключу на месте и переносит имена строк.** — *Принята.* Один ключ (массив из одного элемента + массивы направления/типа) отсортировал колонку по возрастанию; имена строк остались при своих данных.
- **H3. Несколько ключей — последовательные вызовы от младшего к старшему.** — *Принята* как рабочий приём (устойчивость сортировки STATISTICA не документирована, но порядок равных ключей сохранялся в тестах).

**Решение.** Команда `sort`: для каждого ключа (с конца) вызывает `SortDataEx` с учётом направления (`0`/`asc`, `1`/`desc`) и типа (число/текст определяется по `VariableType`). Инструмент `sort_data`.

**Итог.** `Sorted 156 cases x 18 variables`; имена строк переезжают вместе со строками.

## 11. Выбор строк (P1 #9)

**Проблема.** Нужно оставить только строки, удовлетворяющие условию, с уменьшением числа наблюдений.

**Гипотезы:**

- **H1. Использовать COM-метод `FilterCases`.** — *Отложена.* У метода много `out`-параметров (`FilteredSpreadsheet&`, `DuplicatesSpreadsheet&`), а подобные сигнатуры (как `Statistics`) через `CallByName` ненадёжны.
- **H2. Вычислить маску в Node, затем в одном сеансе воркера уменьшить размер (`SetSize`) и перезаписать все колонки отфильтрованными значениями.** — *Принята.* Так как режим stateless, изменение размера и запись обязаны произойти в одном процессе.

**Решение.** Сервер читает переменную условия, вычисляет список 1-based номеров строк и передаёт его команде `select`, которая читает все колонки, вызывает `SetSize(keep, nv)`, записывает отфильтрованные значения и переносит имена строк. Операторы: `gt/ge/lt/le/eq/ne/in/notin/missing/notmissing`, для чисел и текста.

**Итог.** `Kept 144 of 156 cases (12 removed)` для `SERIES_G notmissing`.

## 12. Перекодирование (P1 #9)

**Проблема.** Заменить значения переменной по таблице соответствия.

**Гипотезы:**

- **H1. COM-метод `Recode(Variable, OtherValueMode, OtherValue, SelectionModeArray, SelectionStringArray, DestValueArray)`.** — *Отвергнута.* Вызов через `CallByName` падает с `E_INVALIDARG` (сложные нетипизированные массивы).
- **H2. `recode = read → map в Node → write`.** — *Принята.* Чтение и запись одной колонки не зависят от состояния между процессами: запись полностью замещает значения.

**Решение.** Инструмент `recode`: `map` (старое→новое), опционально `default` для не перечисленных и `missing` для пропусков. Пропуски без `missing` сохраняются.

**Итог.** `Recoded #1 Month: 2 value(s) changed`.

## 13. ANOVA / GLM (P1 #7)

**Проблема.** Не было пресета дисперсионного анализа.

**Гипотезы:**

- **H1. Модуль `2601` (ANOVA) — отдельный простой диалог.** — *Отвергнута.* И `2601`, и `4100` открывают один и тот же многошаговый GLM-диалог.
- **H2. Схема как у GRM: `GLMAnalysisItem=1` → `Run` → `Variables="dep | effects"` → `Run` → `UnivariateResults`/`Coefficients`.** — *Принята.* После второго запуска доступны `UnivariateResults` (таблица ANOVA) и `Coefficients`.

**Решение.** Инструмент `statistica_anova` на модуле 4100: `dependent` + `between`, методы `standard/all_effects/forward/backward`.

**Итог.** Возвращаются таблица эффектов и оценки параметров.

## 14. Факторный анализ (P1 #7)

**Проблема.** Не было пресета факторного анализа.

**Гипотезы:**

- **H1. Один `Run` после установки `Variables` даёт результаты.** — *Отвергнута.* После первого запуска диалог предлагает выбрать метод извлечения, таблиц результатов ещё нет.
- **H2. Двухшаговый мастер: `Variables` → `Run` → выбрать метод (напр. `PrincipalComponents=true`, `NumberOfFactors`) → `Run`.** — *Принята.* После второго запуска доступны `Eigenvalues`, `FactorLoadings`, `Communalities`, `FactorScores`, `ReproducedAndResidualCorrelations`, `ScreePlot`.

**Решение.** Инструмент `statistica_factor` на модуле 2101: методы `principal_components`, `principal_axis`, `centroid`, `maximum_likelihood`, `minres`; опционально число факторов.

**Итог.** Возвращаются собственные значения, нагрузки, общности.

## 15. Лаговая корреляционная матрица (P1 #4)

**Проблема.** Для моделей корреляции НВР нужно одним вызовом получить столбцы `Lag1..LagK`.

**Гипотезы:**

- **H1. Создать K переменных и записать их в одном сеансе.** — *Принята.* Так как stateless, `AddVariables` и запись обязаны быть в одном процессе; добавлена команда `addwrite`.
- **H2. Значения столбцов — корреляционное произведение `x(t)·x(t−L)`, с опциональным сглаживанием SMA.** — *Принята* как рабочая семантика; также поддержан `mode:"shift"` для чистого сдвига.

**Решение.** Сервер читает ряд, считает произведения/сдвиги (и SMA), команда `addwrite` добавляет именованные переменные и пишет значения. Инструмент `statistica_correlation_matrix`.

**Итог.** `Added 3 lag column(s)`; значения совпадают с ручным перемножением (`13216, 15576, …`).

# Часть III. Доработка v2.3 (пункты P2)

Третий круг: устойчивость к модальным окнам, уровни измерения и метки значений, много листовые книги, кластерный анализ, PDF-экспорт и проверка шаблонов `.stg`.

## 17. Модальные окна блокировали автоматизацию

**Проблема.** При headless-прогоне STATISTICA показывала окна, требующие клика: «… may contain features that will be lost … Do you want to export the Spreadsheet in this format?», диалог «Save As Text File:» (разделитель и пр.) и «Save changes to Workbook1?» при выходе. Они останавливали `selftest`.

**Гипотезы:**

- **H1. Достаточно `Application.DisplayAlert = $false`.** — *Отвергнута.* Алерт подавляется, но окна экспорта и подтверждения сохранения остаются: они порождаются самими операциями, а не механизмом алертов.
- **H2. Экспорт через `SaveAs('.csv')` в принципе диалоговый.** — *Принята.* `SaveAs` для текстовых/табличных форматов открывает мастер экспорта. Программные `ExportTextEx`/`ExportXLS` пишут файл напрямую без окна.
- **H3. Пометки `Saved = $true` на документах достаточно, чтобы `Quit()` не спрашивал.** — *Отвергнута.* Замер: `saved`-стратегия дала `Quit` за 14.4 с (окно всё равно ждало пользователя), тогда как закрытие документов — 37 мс.
- **H4. Перед выходом нужно закрыть документы с `Close(SaveChanges=$false, ...)`.** — *Принята.* Для графов, рабочих книг, листов и отчётов; окно не появляется.

**Решение.** `export_csv`/`save_as` (`.csv`/`.xlsx`) переведены на `ExportTextEx`/`ExportXLS`; перед `Quit` воркер вызывает `Close-AllDocuments` (графы → рабочие книги → листы → отчёты, `Close($false)`), плюс `Application.DisplayAlert = $false`.

**Итог.** `selftest` проходит без ручных кликов; добавлены проверки `.xlsx` и CSV с разделителем.

## 18. Уровни измерения и метки значений (P1 #6)

**Гипотезы:**

- **H1. `VariableMeasurementType` доступно только на чтение.** — *Отвергнута.* `comSet $ss 'VariableMeasurementType' @($idx, $type)` меняет уровень (проверено: `2` → `3`).
- **H2. Метки значений задаются `SetTextLabel`.** — *Принята.* `SetTextLabel(var, value, label, description)` записывает; `NumberOfTextLabels`, `TextLabelValue`, `TextLabelDescription` читают; `RemoveAllLabels` сбрасывает.

**Решение.** Команды `set_measurement` и `labels`, инструменты `set_measurement` и `value_labels`. Уровень измерения нужен, чтобы GLM трактовала переменную как фактор.

**Итог.** `set_measurement { type:"categorical" }`, `value_labels { labels:{112:"LOW"} }` работают.

## 19. Много листовые книги (P2 #13)

**Гипотезы:**

- **H1. Много листовые книги — отдельный механизм.** — *Отвергнута.* `Open-Sheet` уже перечисляет листы одного воркбука как элементы `Application.Spreadsheets`; выбор по имени/индексу поддержан во всех инструментах через параметр `sheet`.
- **H2. Не хватает только обзорного инструмента.** — *Принята.* Добавлен `list_sheets` (индекс, имя, размер) через команду `sheets`.

**Итог.** `list_sheets` возвращает список листов; `sheet` работает во всех инструментах.

## 20. Кластерный анализ (пресет)

**Гипотезы:**

- **H1. Модуль 2201 — одношаговый.** — *Отвергнута.* Это мастер: первый `Run` открывает диалог спецификаций, где доступно `Variables`.
- **H2. `ClusterMembership` читается сразу.** — *Отвергнута.* Свойство отдаёт `E_FAIL`. Доступны `AmalgamationSchedule`, `DistanceMatrix`, `DescriptiveStatistics`.

**Решение.** `statistica_cluster` на модуле 2201: `Run` → `Variables` → `Run` → расписание, матрица расстояний, статистики.

**Итог.** Пресет отдаёт таблицы; членство в кластерах доступно через GUI-настройку среза дерева (в COM не выставлено).

## 21. PDF-экспорт (P2 #11)

**Гипотезы:**

- **H1. `SaveAsPDF` зависает.** — *Отвергнута (в этой сборке).* `SaveAsPDF`, `SaveAsPDFEx` завершаются быстро, но возвращают `False` и файла не создают.
- **H2. `SaveAsFormat(path, PDF)` сработает.** — *Отвергнута.* Возвращает `False`; `SaveAs('.pdf')` — `False`. JPEG-экспорт также падает (`E_FAIL`), тогда как PNG и EMF пишутся.
- **H3. Собрать PDF из PNG средствами Node.** — *Принята.* PNG распаковывается (inflate, дефильтрация строк), упаковывается обратно (deflate) как `/FlateDecode`-изображение на одной странице PDF.

**Решение.** `src/pdf.mjs` (конвертер PNG→PDF на `node:zlib`); `analysis()` перехватывает `saveGraph` c расширением `.pdf`, просит воркер сохранить PNG во временный файл, конвертирует и удаляет временный. PDF собирается с корректным `xref` (проверено: `startxref` указывает на `xref`).

**Итог.** `statistica_graph { out:"…pdf" }` создаёт валидный растровый PDF.

- **H1. `.stg` можно открыть и применить через COM.** — *Частично.* `Application.Open('…stg')` открывает шаблон как граф-документ (в `Application.Graphs` появляется элемент «Scatterplot»).

**Итог.** Открытие `.stg` возможно, применение — нет.

## 24. Скриншот окна STATISTICA

**Проблема.** Для отчёта нужны картинки реальных окон программы: как открылась таблица данных, как меняются значения, как построен график.

**Гипотезы:**

- **H1. `PrintWindow` главного окна даст содержимое документа.** — *Отвергнута.* Снимок 2576×1327 содержал только каркас (меню/панели), а дочерние MDI-окна (таблица, график) не отрисовывались.
- **H2. Достаточно показать окно и снять экран.** — *Принята.* `Application.Visible=$true` + `ShowWindow(SW_MAXIMIZE)` + `SetForegroundWindow`, затем `Graphics.CopyFromScreen` по прямоугольнику окна даёт реальные пиксели — включая содержимое документа.
- **H3. Нужно активировать конкретный документ.** — *Принята.* Без активации в кадре пустая рабочая область. `Spreadsheet.Activate()`/`Graph.Activate()` выводят нужное окно на передний план.
- **H4. Можно снять только документ.** — *Принята.* Перечисление дочерних окон `MDIClient` (класс `Afx:…`) даёт активное окно документа `Data: … (Nv by Mc)` или `Scatterplot …`; режим `document` снимает только его (972×767 график, 2186×751 таблица).
- **H5. Прямоугольник окна обрезается из-за DPI.** — *Принята.* Процесс PowerShell не был DPI-aware, поэтому `Screen.Bounds`/`CopyFromScreen` возвращали виртуализованные 2560×1359 вместо физических 5120×2718. Вызов `SetProcessDPIAware()` в начале воркера даёт полный экран в реальном разрешении.
- **H6. Свёрнутое окно не попадает в кадр.** — *Принята.* `SetForegroundWindow` игнорируется из-за блокировки фокуса, и снимался рабочий стол. Решение: `ShowWindow(SW_RESTORE→SW_MAXIMIZE)`, `AppActivate(pid)`, `SwitchToThisWindow`, `BringWindowToTop`, ожидание `GetForegroundWindow()==окно`; снимок берётся со всего `SystemInformation.VirtualScreen` (все мониторы). Если фокус не получен — ответ содержит предупреждение.

**Решение.** Инструмент `statistica_screenshot { out, path?, module?, variables?, mode?, waitMs? }`: контент строится, пока окно скрыто (построение графа в видимом окне иногда падает с `E_FAIL`), затем окно показывается, документ активируется и снимается (`mode`: `window` по умолчанию, `document` — только активное окно). Для «вживую» в `attach`-режиме можно сперва изменить значения (`write_variables`/`set_formula`), затем снять таблицу.

**Дополнительно.** Обнаружен разовый `E_FAIL` при создании COM из-за зависших экземпляров; добавлен `New-ComApp` (до 3 попыток) и безопасная очистка `Close-App`, чтобы сбой уборки не ломал результат команды.

**Итог.** Снимки с реальным содержимым (проверено: десятки различных пикселей, не пустой кадр).

## 25. Блоки методички ЛР3 (модель корреляции НВР)

**Проблема.** Для прохождения ЛР3 не хватало операций: запаздывание ряда (Shift), центрированное сглаживание SMA и линия аппроксимации на графике.

**Гипотезы:**

- **H1. Запаздывание недоступно.** — *Отвергнута.* Панель Transformations даёт `ShiftSeriesForward` + `LagForShiftingSeriesForward` (и `ShiftSeriesBack` + `LagForShftingSeriesBackward`). Добавлена процедура `shift`.
- **H2. `NPointsMovingAverage` даёт SMA(12,6).** — *Принята* с уточнением: центрированность задаётся `ComputeMovingAverageFromPriorValues=false`; окно = период. Добавлен флаг `prior`.
- **H3. Совмещённый график даёт `PlotMultipleVariables`.** — *Отвергнута.* Сеттер роняет STATISTICA (`0x800706BA` RPC unavailable) и открывает окно выбора переменных. Рабочий путь — `statistica_graph` 11012 с `GraphType=1` (один граф с несколькими линиями).
- **H4. 3D Surface — отдельный модуль.** — *Отвергнута.* Достаточно 11021 (3D Raw Data Plots) с `GraphType=6` (`sc3DRawSurface`); 11032 требует синтаксис `X|Y|Z` и иначе открывает окно выбора.
- **H5. Линию аппроксимации можно добавить на график через COM.** — *Отвергнута.* Вместо этого МНК считается в Node, fitted-значения пишутся переменной (`add_fit_line`), и линия рисуется рядом с данными.

**Решение.** `statistica_time_series` получил `shift` и центрированное сглаживание; добавлен `add_fit_line`; multi-line и 3D Surface задаются `properties.GraphType`; `saveGraph` научился сохранять результат-массив (11012 отдаёт несколько графов).

**Итог.** Операции ЛР3 (АКФ → shift → произведение → SMA → fit → 3D) выполнимы.

## 25f. Макросы SVB (ЛР6–8)

**Проблема.** В ЛР6, ЛР7 и ЛР8 рекуррентные модели (DWLS, Lowess, EWPR) не являются готовыми процедурами пакета — они заданы исходным кодом на STATISTICA BASIC (SVB) в приложении к методичке. Без исполнения макросов эти лабораторные не выполнить.

**Гипотезы:**

- **H1. SVB-код можно выполнить через COM.** — *Принята.* `Application.Open('.svb')` открывает макрос, `Macro.Code` его хранит, `Macro.Execute()` выполняет.
- **H2. `ActiveSpreadsheet` внутри макроса указывает на открытый лист.** — *Отвергнута по умолчанию.* После открытия `.svb` активным документом становится сам макрос, и `ActiveSpreadsheet` = `Nothing` («значение переменной типа Object равно Nothing»). Решение: перед `Execute()` вызвать `Spreadsheet.Activate()`.
- **H3. Незакрытый макрос не мешает выходу.** — *Отвергнута.* При `Quit` появляется окно «Save changes to sta-macro?»; `Macros` добавлены в `Close-AllDocuments`.

**Решение.** Команда воркера `macro` и инструмент `run_macro { path?, code?|source?, save? }`: пишет код во временный `.svb` (или берёт файл), открывает, активирует лист и выполняет; результат листа можно сохранить через `save`.

**Итог.** Проверено: макрос `s.Cells(1,1)=999` меняет данные (`v1[0]` 1 → 999). Относится к ЛР6–8, не к ЛР3.

## 25g. Модели экспоненциального сглаживания (ЛР4) и блоки ЛР1–ЛР2

**Проблема.** Для ЛР4 нужны модели Хольта, Тейла–Вейджа и Уинтерса с параметрами сглаживания; для ЛР1/ЛР2 — взвешенная полиномиальная аппроксимация и проверка нормальности.

**Гипотезы:**

- **H1. `exponential_smoothing` умеет только простой EMA.** — *Отвергнута.* Панель ES даёт свойства-модели `NoTrendNoSeasonalCompononent` (EMA), `NoTrendAdditive/Multiplicative`, `LinearTrendNoSeasonalCompononent` (Хольт), `LinearTrendAdditiveSeasonality` (Тейл–Вейдж), `LinearTrendMultiplicativeSeasonality` (Уинтерс), `DampedTrend*`, `ExponentialTrend*`, а также `ParameterAlpha/Gamma/Delta`, `SeasonalLag`, `ForecastNCases`. Добавлен параметр `model`.
- **H2. Аппроксимация только линейная.** — *Отвергнута.* `add_fit_line` обобщён до степени `degree` (МНК через нормальные уравнения).
- **H3. Нормальность — отдельный модуль.** — *Отвергнута.* Это вкладка Normality в Basic Statistics: `ShapiroWilkWTest`, `KSAndLillieforsTestForNormality`, `Histograms` (последнее — метод; чтение результата `Histograms` даёт гистограмму).

**Решение.** `exponential_smoothing` получил `model` и параметры; `add_fit_line` — степень; добавлен `statistica_normality` (описательные + тесты + гистограмма).

**Итог.** ЛР4 (EMA/Хольт/Тейл–Вейдж/Уинтерс) и шаги нормальности ЛР2 выполнимы.

## 25j. Постоянное окно и работа через `attach`

**Проблема.** Обычный режим закрывает `statist.exe` после каждого вызова; для ручного ввода данных и живых правок нужно **не закрывать** окно.

**Гипотезы:**

- **H1. `attach` уже работает с открытым окном.** — *Принята*, но окно приходилось открывать вручную.
- **H2. Инструмент может сам запустить и оставить окно.** — *Принята.* `New-Object`/`GetActiveObject` + `Visible=$true` без `Quit`; воркер завершается, а `statist.exe` остаётся.
- **H3. `attach` требует `path`.** — *Отвергнута.* Путь можно опустить — воркер возьмёт `ActiveSpreadsheet`; `requirePath` разрешает пустой путь при `attach`.
- **H4. `GetActiveObject` вернёт именно наше окно.** — *Отвергнута* при нескольких копиях: возвращается первый зарегистрированный экземпляр. Решение: `statistica_open` переиспользует уже запущенный экземпляр, поэтому `attach` попадает в то же окно.

**Решение.** Инструмент `statistica_open { path?, sheet? }` (команда `open`, `$keepAlive` — без `Close-App`/`Quit`); `attach` без `path` работает с активным листом.

**Итог.** Проверено на живом окне: `set_formula`, `statistica_graph` и `statistica_screenshot` с `attach:true` правят/рисуют/снимают без перезапуска приложения.
