## B-1. Пропуски не распознаются (высокая)

### Симптом
`descriptives` показывает `N = 311` при 311 наблюдениях и `missing = 0`, а `min = -9999`. То есть значения пропуска попадают в статистику и сильно занижают среднее и минимум.

Фактический вывод:

```
variable                       N   missing      mean         sd    min         q1    median
!~\FT1,,,\c0,TS_Nrm          311          0  -5369.23351  4993.849302  -9999  -9999  -9999
```

Для корректного расчёта ожидалось примерно `mean ≈ -0.4`, `N < 311`.

### Воспроизведение
```
statistica_info
descriptives  { "path": "C:\\Users\\user\\Documents\\АВР\\ЛР3\\LAB3.sta" }
```

### Ожидаемое / фактическое
* Ожидается: пропуски исключены, `N` меньше общего числа строк.
* Фактически: все 311 значений приняты за данные.

### Причина
В `sta.ps1` пропуск определяется сравнением ровно с одним значением:

```powershell
$MISSING = -999999998.0
...
if ($v -eq $MISSING) { $out[$i] = $null }
```

В реальности в STATISTICA различаются **два** маркера:

| Маркер | Что это | Откуда известно |
|---|---|---|
| `-999999998` | значение, которое `VData` возвращает для ячейки, в которую никогда не записывали | наблюдение на вновь созданных колонках в `api11`/`api12` |
| `-9999` | код пропуска, **объявленный самой переменной** в этом файле | `describe_spreadsheet` → поле `missingValue` = −9999 у всех 10 переменных `LAB3.sta` |

Данные `LAB3.sta` содержат `-9999`, поэтому текущая проверка их не ловит. Подтверждение: `VData` отдаёт `-9999` как обычное число, а `descriptives` включает его в выборку.

### Предлагаемое исправление
В функции `Read-Variable` получать код пропуска переменной и считать пропуском оба значения:

```powershell
$mdCode = [double](comGet $ss 'VariableMissingData' @($idx))
...
if ($v -eq $MISSING -or $v -eq $mdCode) { $out[$i] = $null }
```

Заодно стоит проверить альтернативный путь: у `_Spreadsheet` есть `get_VDataWithoutMD(VarNo)`. Если он возвращает колонку уже без пропусков, чтение можно упростить. **Не проверено.**

### Риск исправления
Нужно убедиться, что `-9999` не встречается как обычное значение. Если в других файлах код пропуска другой (например `-99999`), сравнение с фиксированной константой не подойдёт — только вариант с чтением `VariableMissingData`.

## B-2. `read_variables` не выводит номер колонки (низкая)

### Симптом
```
variable undefined: !~\FT1,,,\c0,TS_Nrm  [numeric, 3 values from case 1]
```

### Причина
Функция `Read-Variable` в `sta.ps1` формирует ответ без поля `index`:

```powershell
return @{ name = ...; longName = ...; type = $type; ... }
```

а `server.mjs` печатает `d.index`:
```javascript
lines.push(`variable ${d.index}: ${d.name}  [...]`)
```

### Исправление
Добавить `index = $idx` в возвращаемый хеш.

### Риск
Нет. Но номер колонки сейчас особенно полезен — см. B-3 и B-4.

## B-3. Новая переменная не находится по имени (средняя)

### Симптом
```
add_variables   { "name": "TS_Mul_probe", "after": 10 }   →  OK, «added #11 TS_Mul_probe»
write_variables { "columns": [{ "name": "TS_Mul_probe", ... }] }
                →  ERROR: variable not found: 'TS_Mul_probe'
```

### Воспроизведение
Оба вызова подряд на одном файле. Если разделить их и сохранить файл на диск между вызовами, ошибки нет.

### Причина (гипотеза, высокая уверенность)
`VariableNumber(name)` работает корректно для переменных, загруженных из файла — проверено: `VariableNumber('Res_1')` вернул `4`. Для переменной, созданной через `AddVariables` в текущей сессии, метод возвращает неположительное значение, то есть не находит её. Похоже, внутренний индекс имён не обновляется для новых переменных до сохранения.

Подтверждающие наблюдения:
* `describe` сразу после `AddVariables` показывает переменную корректно;
* тот же `VariableNumber` после переоткрытия сохранённого файла работает;
* ошибка воспроизводится стабильно.

### Исправление
В `Get-VarIndex` при неудачном `VariableNumber` сделать линейный перебор:

```powershell
$i = comCall $ss 'VariableNumber' @($key)
if ($null -eq $i -or [int]$i -le 0) {
  for ($k = 1; $k -le [int]$ss.NumberOfVariables; $k++) {
    if ([string](comGet $ss 'VariableName' @($k)) -eq $key) { return [int]$k }
  }
  throw "variable not found: '$key'"
}
```

### Риск
Низкий. Перебор медленный только для файлов с тысячами переменных.

## B-4. Имена переменных содержат внутренние префиксы (средняя)

### Симптом
`describe_spreadsheet` возвращает:

```
1  !~\FT1,,,\c0,Month
2  !~\FT1,,,\c0,TS_Nrm
4  !~\FT1,,,\c0,Res_1
10 ACF(1)
```

Ожидались `Month`, `TS_Nrm`, `Res_1`, `ACF(1)`.

### Причина
Это способ хранения коротких имён в STATISTICA 12: префикс `!~\FT1,,,\c0,` — служебная часть, кодирующая исходную переменную и её преобразования, а `TS_Nrm` — собственно имя. Формат документирован только косвенно.

### Исправление
Добавить в `describe` и `read` производное «чистое» имя — всё после последней запятой:

```powershell
function Get-CleanName($raw) {
  $i = $raw.LastIndexOf(',')
  if ($i -ge 0 -and $i -lt $raw.Length - 1) { return $raw.Substring($i + 1) }
  return $raw
}
```

и принимать в `Get-VarIndex` как имя, так чистое, так и полное.

### Риск
Три замечания:
1. Имя может законно содержать запятую — тогда будет обрезано.
2. Две переменные могут дать одинаковое чистое имя — нужен fallback на полное имя.
3. Требует проверки на реальных файлах, где префиксов нет (`ACF(1)`), чтобы не сломать их.

## B-5. `sheetIndex: 0` (косметическая)

`describe_spreadsheet` без параметра `sheet` сообщает `Sheet: LAB3 (index 0)`, хотя реально открыт первый лист. Причина: `[int]$req.sheet` при `null` даёт `0`. Исправляется возвратом фактически использованного индекса из `Open-Sheet`.

## B-6. Экспорт может быть не завершён к моменту возврата (низкая)

Один раз `SaveAs` в CSV вернул управление, и файл сразу не находился (`Не удается найти путь ... sta_out.csv`), при повторной попытке всё отработало. Возможно, это задержка вывода на диск. Надёжность повысит проверка `Test-Path` с несколькими короткими повторами и небольшой паузой перед тем, как считать размер файла.

На практике проблема не проявлялась в последующих прогонах.

## Сознательно не реализовано

Не баги, но ограничения, о которых нужно знать.

### Экспорт в PDF
`SaveAsPDF` в headless-режиме **вешает процесс** — `statist.exe` не завершается, скрипт не отвечает более 5 минут, пришлось убивать процесс принудительно. Инструмент намеренно не реализован.

### Запись формул STATISTICA
Формулы (`=v7*v8`) хранятся в длинных именах и вычисляются самой программой. Записать формулу через COM не удалось: `SetData` со строкой-формулой даёт либо `Invalid parameter Value`, либо `E_INVALIDARG`. Проверка `IsValidFormula` работает, формулу она только валидирует, но не применяет.

Практический обход: прочитать нужные колонки, выполнить вычисление в JS, записать результат как обычную числовую переменную. Запись числовой колонки векторизована, так что это быстро.

### Методы с out-параметрами
`Statistics`, `ColumnStats`, `Recalculate` требуют `out`-параметры, которые `CallByName` не передаёт (`DISP_E_TYPEMISMATCH`, `Invalid cases parameter`). Поэтому описательные статистики считаются в Node.js, а не в STATISTICA. Результат идентичен, но используется независимая реализация.

### Скорость
Каждый вызов инструмента запускает новый процесс `statist.exe` и закрывает его — из-за того, что COM-объект не переживает границу процессов PowerShell. Отсюда задержка в несколько секунд на вызов и невозможность держать открытый документ между вызовами. Реализация сделана намеренно stateless: так поведение предсказуемо, а изменение исходных файлов требует явного параметра `save`.
